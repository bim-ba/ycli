Если работа вашей команды организована на основе *гибких методологий разработки (Agile)*, попробуйте использовать доски задач в Трекере. На доске удобно отслеживать текущие задачи команды, например во время ежедневных собраний. Задачи отображаются на доске в виде карточек, которые распределены по колонкам в зависимости от статуса.

Вы можете [создать несколько досок задач](https://yandex.ru/support/tracker/ru/manager/agile-create), например для разных рабочих групп или для задач разного типа:

1. На панели слева выберите  **Доски задач**, затем нажмите **Создать доску**.

2. Выберите [тип доски](https://yandex.ru/support/tracker/ru/dev-process-agile#board_types).

3. Для добавления задач нажмите кнопку **Добавить задачи**. В открывшемся окне выберите, какие задачи автоматически добавлять на доску, а также задайте условия фильтра, чтобы отображать на доске задачи с определенными параметрами.

Например, вы можете настроить фильтр, чтобы на доску попадали все задачи из вашей очереди, задачи с указанными [компонентами](https://yandex.ru/support/tracker/ru/manager/components), задачи указанных сотрудников и так далее.

# Типы досок в Трекере

В Трекере можно использовать два типа досок:

- «Простая» — доска с минимальными возможностями, отображает задачи команды и их статус.

- «С бэклогом и спринтами» — кроме отображения статусов задач, позволяет управлять [спринтами](https://yandex.ru/support/tracker/ru/dev-process-agile#sprints), [бэклогом](https://yandex.ru/support/tracker/ru/manager/backlog), [оценивать задачи](https://yandex.ru/support/tracker/ru/dev-process-agile#poker) и смотреть [диаграмму сгорания задач](https://yandex.ru/support/tracker/ru/dev-process-agile#burndown).

# Инструменты на доске «С бэклогом и спринтами»

На доске «С бэклогом и спринтами» доступны инструменты, которые помогут организовать работу по методологии Скрам. [Что такое Скрам](https://ru.wikipedia.org/wiki/SCRUM)

## Спринты

В методологии Скрам работа выполняется небольшими итерациями — *спринтами*. Обычно спринт длится одну или две недели. Старайтесь планировать спринты так, чтобы за время спринта команда успела выполнить все намеченные задачи. Чтобы понимать объем запланированной работы, предварительно оцените задачи с помощью [покера планирования](https://yandex.ru/support/tracker/ru/manager/poker).

- Нажмите в правой части доски кнопку **Создать спринт**.

- [Создайте спринт](https://yandex.ru/support/tracker/ru/manager/create-agile-sprint#create_sprint): выберите его название, длительность и задайте даты начала и конца спринта.

- Добавьте в спринт задачи: перетащите задачи из столбца **Бэклог** в список задач спринта или на странице задачи укажите спринт в поле **Agile** → **Спринт**.

[Как запланировать спринт в Трекере](https://yandex.ru/support/tracker/ru/manager/create-agile-sprint)

Чтобы отобразить на доске задачи определенного спринта, выберите спринт вверху страницы. Чтобы следить за скоростью выполнения задач, запланированных в спринте, используйте [диаграмму сгорания](https://yandex.ru/support/tracker/ru/manager/burndown-diagram).

## Покер планирования

Чтобы точно спланировать объем работы в следующем спринте, нужно оценить трудоемкость задач. Для этого в методологии Скрам используется покер планирования (Planning Poker). Этот метод позволяет получить независимые оценки задачи от всех участников команды, обсудить их и сформировать итоговую оценку. Обычно для оценки используют относительную единицу трудоемкости задач Story Point.

- Чтобы провести оценку, попросите участников команды перейти на страницу покера. Для этого на доске задач нажмите кнопку  **Покер** и скопируйте ссылку для приглашения участников.

- В настройках доски можно задать шкалу оценки задач и правила вычисления итоговой оценки.

[Как использовать покер планирования в Трекере](https://yandex.ru/support/tracker/ru/manager/poker)

## Диаграмма сгорания

Диаграмма сгорания показывает скорость выполнения задач и оставшийся объем работы в течение спринта. По ней можно спрогнозировать, успеет ли команда выполнить запланированные задачи.

На диаграмме по вертикальной оси отмечен суммарный объем оставшейся работы в единицах Story Point, по горизонтальной — время. Идеальная диаграмма сгорания должна быть близка к прямой линии, которая начинается в точке с максимальным объемом работы (общий объем задач в спринте) в первый день спринта и заканчивается в нулевой точке в последний день спринта.

Чтобы посмотреть диаграмму, на доске задач нажмите вкладку **Диаграмма сгорания**. [Как использовать диаграмму сгорания](https://yandex.ru/support/tracker/ru/manager/burndown-diagram)

# Декомпозиция задач

В гибких методологиях разработки задачи декомпозируют следующим образом:

- Крупные задачи, которые невозможно выполнить в течение одной итерации (спринта), называют эпиками (Epics).

- Эпики разбивают на «пользовательские истории» (User Stories) — законченные возможности продукта, которые можно реализовать за один спринт.

- Истории разбивают на отдельные задачи, например дизайн интерфейса, разработка бэкенда и разработка фронтенда.

Чтобы использовать такую систему декомпозиции задач, в [шаблоне очереди «Разработка»](https://yandex.ru/support/tracker/ru/manager/work-process#development) предусмотрены типы задач Epic и Story. Если [при создании очереди](https://yandex.ru/support/tracker/ru/dev-process-create-queue) вы выбрали шаблон, в котором нет типов задач Epic и Story, вы можете [добавить их в настройках очереди](https://yandex.ru/support/tracker/ru/manager/add-ticket-type).
