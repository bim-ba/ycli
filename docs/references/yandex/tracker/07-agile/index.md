Доска задач — это инструмент для наглядного управления задачами и отслеживания их статуса. Например, можно создать доску, на которой вы будете видеть все задачи вашей команды.

Доска разделена на несколько вертикальных колонок, которые обозначают этап рабочего процесса. Задачи на доске обозначены карточками — аналогами бумажных стикеров. Сотрудники могут видеть видеть на доске задачи команды, распределять их между собой и перемещать по колонкам по мере продвижения работы.

Как пользоваться доской задач, написали в разделе [Как работать с задачами на доске](https://yandex.ru/support/tracker/ru/manager/agile-issues).

# Принципы работы с досками

Количество задач на досках не может превышать 2000, поэтому рекомендуем придерживаться следующих принципов:

- На доску добавляйте только те задачи, которые планируете сделать в ближайшее время (например, за ближайшие полгода).
- Чтобы доски не переполнялись, настройте [автоудаление](https://yandex.ru/support/tracker/ru/manager/agile-set-board#autodelete) — задачи в определенном статусе будут автоматически удаляться с доски.
- Чтобы анализировать закрытые задачи, которые с доски уже удалили, используйте страницу [поиска задач](https://tracker.yandex.ru/issues) или, если вы используете доску **С бэклогом и спринтами**, на вкладке **Бэклог** вы увидите ссылку на фильтр с задачами закрытого спринта.
- Для работы со всеми своими задачами (например, для общего анализа с помощью фильтров или сортировок) используйте очереди — не стремитесь все задачи добавить на доску.

# Что такое гибкие методологии разработки

Гибкие методологии разработки (Agile) были созданы для управления разработкой программного обеспечения. Теперь их успешно применяют для управления проектами и процессами в самых разных областях.

Инструменты гибкой разработки в Трекере заимствованы из популярной методологии, которая называется Скрам. Скрам включает набор практик, ролей и инструментов, которые помогают организовать командную работу. [Что такое Скрам](https://ru.wikipedia.org/wiki/SCRUM)

Бэклог

Список задач или требований к продукту, которые нужно реализовать в проекте. Обычно задачи в бэклоге упорядочены по приоритету. [Как использовать бэклог](https://yandex.ru/support/tracker/ru/manager/backlog)

Спринт

Итерация работы над проектом, обычно длится 1–4 недели. Считается, что в каждом спринте команда должна разработать и подготовить к выпуску новые функции продукта (инкремент). [Как использовать спринты](https://yandex.ru/support/tracker/ru/manager/create-agile-sprint)

Покер планирования

Метод командной оценки сложности задач с помощью карт, на которые нанесены оценки сложности в относительных единицах *Story Points*. [Как оценивать задачи с помощью покера](https://yandex.ru/support/tracker/ru/manager/poker)

Доска задач

Доска для отслеживания статуса задач в текущем спринте. Столбцы на доске соответствуют статусам задач. Карточки с описанием задач прикрепляются на доску и перемещаются между [столбцами](https://yandex.ru/support/tracker/ru/manager/agile-columns) по мере изменения статуса.

Диаграмма сгорания задач

График, который показывает скорость выполнения запланированных задач в течение спринта и объем оставшейся работы. [Диаграмма сгорания задач](https://yandex.ru/support/tracker/ru/manager/burndown-diagram)

User Story

«Пользовательская история» — описание возможности, которую нужно реализовать в продукте, с точки зрения потребностей или проблем пользователя. User Story разбивается на отдельные задачи. В Трекере можно использовать тип задач Story для группировки любых задач с общей темой. [Как использовать эпики и истории](https://yandex.ru/support/tracker/ru/manager/epic).

Story Point

Относительная единица трудоемкости задач. Обычно единица Story Point не эквивалентна какому-то определенному количеству человеко-часов. Команда оценивает задачи совместно, сравнивая их с какой-нибудь простой задачей. [Как оценивать задачи с помощью покера](https://yandex.ru/support/tracker/ru/manager/poker)

Эпик

Крупная функция или требование, которое невозможно реализовать за один спринт. Обычно разбивается на несколько историй (User Story) или задач. В Трекере можно использовать тип задач Epic для группировки любых задач с общей темой. [Как использовать эпики и истории](https://yandex.ru/support/tracker/ru/manager/epic)

Подэпик

Задача, которая входит в эпик.
